# Alcance funcional de la entrega

Se mantienen las 30 historias, sus responsables y los 174 SP originales. Esta
matriz distingue la implementación entregada de una validación académica de campo.
El piloto se entrega como propuesta documental por decisión del responsable.
No hay participantes ni consentimientos registrados y no se demuestra eficacia educativa.

| Historias | Evidencia de entrega |
| --- | --- |
| PB-01–PB-03 | Configuración y acceso, sesiones/intentos propios y versiones inmutables, probados por API/interfaz. |
| PB-04 | Esquema/guía pedagógica y ejemplos sintéticos. Las revisiones humanas permanecen sin aplicar. |
| PB-05 | Exportador histórico con autorización explícita; la entrega utiliza solo sintéticos y no exportó historia real. |
| PB-06 | 144 variantes observadas y 36 controles AC, seis problemas y seis lenguajes en el juez fijado. |
| PB-07 | Validación estricta, planillas con hash, decisiones todo o nada y prohibición de autorrevisión; el modo técnico conserva borradores. |
| PB-08 | Dataset versionado con hashes, semilla y particiones por problema 96/24/24, sin contaminación. |
| PB-09–PB-10 | Explicadores conservadores de compilación/ejecución/recursos y límites de inferencia a partir de veredictos. |
| PB-11–PB-12 | Clasificador entrenado y evaluado sobre test separado; cuatro categorías representadas, sin afirmar cobertura semántica completa. |
| PB-13 | Dos candidatos medidos realmente; selección técnica documentada del modelo de menor latencia y memoria. |
| PB-14–PB-15 | Notebook/entrenador y ajuste QLoRA real de tres épocas; adaptador y registros de hardware/entorno/hash. |
| PB-16 | Comparación técnica base/ajustado sobre test sintético; la evaluación pedagógica humana queda como ampliación. |
| PB-17 | Motor interno, conversión GGUF, clasificador, manifiesto y perfil explícito de demostración experimental. |
| PB-18–PB-19 | Endpoint autenticado, propiedad, CSRF, cuotas e idempotencia; contexto por lista positiva sin datos internos. |
| PB-20–PB-21 | Panel Vue 2 con fuente/incertidumbre, último intento resuelto por servidor y valoración única. |
| PB-22–PB-23 | Tres niveles progresivos con nuevo intento posterior y explicaciones de conceptos versionadas. |
| PB-24 | Guard y regresiones, aislamiento de contexto y salida; el guard no garantiza ausencia semántica de soluciones. |
| PB-25–PB-27 | Exclusión de concursos, respaldo/circuito/plazos compartidos y métricas agregadas con retención explícita. |
| PB-28 | Suite, navegador, juez, actualización/recuperación, carga, CI y auditorías; sin certificación de infraestructura externa. |
| PB-29 | Protocolo/instrumentos como propuesta no ejecutada, fuera del requisito de cierre funcional autorizado. |
| PB-30 | Operación, recuperación, guía de uso, demo reproducible, guion/preguntas y registro de versiones/evidencia. |

La mascota, temas, conservación de datos y modernización del backend son requisitos
transversales. La instalación real permanece a cargo del operador y requiere su
propio ensayo con una copia autorizada; los contenedores locales no la sustituyen.
